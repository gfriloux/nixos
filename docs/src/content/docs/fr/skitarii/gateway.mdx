## Conteneurs

Tous sur le réseau Docker `pangolin` (IPv4 + `fd49:e7d1:9e38::/64`). Nix :
`docker-pangolin.nix`, `docker-crowdsec-manager.nix`, relic crowdsec dans `default.nix`.

| Conteneur | Image | Rôle |
|---|---|---|
| `gerbil` | `fosrl/gerbil` | Publie 80/443 TCP et 443/51820/21820 UDP (WireGuard pour newt) |
| `traefik` | `traefik` | Tourne dans le netns de gerbil. Let's Encrypt HTTP-01, plugins badger + bouncer crowdsec |
| `pangolin` | `fosrl/pangolin:ee-*` | Dashboard et API, SQLite dans `/srv/docker/pangolin.friloux.me/config`. Licence EE personnelle gratuite dans `/admin/license` |
| `crowdsec` | `crowdsecurity/crowdsec` | Relic STC, lit le log d'accès de traefik, AppSec sur `:7422` |
| `crowdsec-manager` | `hhftechnology/crowdsec-manager` | UI CrowdSec, socket Docker brut |

## D'où vient la configuration

| Source | Contenu | Écrit par |
|---|---|---|
| Fournisseur HTTP de traefik | Ressources, routes, règles d'auth | pangolin, en direct, depuis sa base |
| `dynamic_config.yml` | Routes du dashboard, middlewares `badger`, `crowdsec`, `redirect-to-https` | Nix (lecture seule) |
| `traefik_config.yml` | Entrypoints, plugins, ACME, log d'accès | Nix (lecture seule) |
| `config.yml` de pangolin | URL du dashboard, domaine `friloux.me`, flags | Template sops (`server.secret`) |

crowdsec-manager ne peut pas éditer les fichiers de traefik : ces changements passent par Nix.

Secrets dans `secrets/skitarii.yaml` : `services/pangolin/secret`,
`services/crowdsec/bouncer-key` (enregistrée en `BOUNCER_KEY_traefik`, lue par traefik dans un fichier monté).

## Publier un service

1. CNAME `<nom>` → `skitarii.friloux.me.` chez Gandi, **avant** toute requête sur ce nom (un `NXDOMAIN` en cache dure 3 h).
2. pangolin : une ressource sur le bon nœud. **Local** pour un conteneur du réseau `pangolin` de skitarii, un nœud newt sinon.
3. Garder le SSO sauf pour un service public. **Enregistrer** l'onglet d'authentification : un SSO désactivé sans enregistrer reste actif, et un navigateur avec une session dashboard le masque (`curl` reçoit `401`).

`photos.friloux.me` n'a pas de SSO (l'app Immich ne passerait pas). Le scénario
crowdsec `LePresidente/http-generic-401-bf` bannit les rafales de `POST` répondues en 401.

## Ajouter un nœud newt

1. pangolin : **Nœuds** → ajouter un nœud, type **Newt**. Copier l'id et le secret (affichés une fois).
2. Fichier sops de l'hôte : `services/newt/id`, `services/newt/secret`.
3. Reprendre le `docker-newt.nix` de RogueLeader : newt sur le réseau des services qu'il sert (`web`). Sans traefik local, créer `web` avec `stc.lib.docker.mkNetwork` (voir celui de clochette).
4. Déployer. `docker logs newt` affiche `Tunnel connection to server established successfully!`, le nœud passe **Online**.
5. Cibles des ressources : nom du conteneur et port interne (`http://mealie:9000`).

Le trafic tunnelé passe quand même par le traefik de skitarii : le bouncer voit
le vrai visiteur et les bans s'appliquent.

## crowdsec-manager

Ressource pangolin `crowdsec.friloux.me` (nœud local, `http://crowdsec-manager:8080`),
derrière le SSO **et le TOTP**. Il a le socket Docker brut : l'atteindre, c'est root sur skitarii.

:::caution
Les clés de sécurité pangolin sont un moyen de connexion, pas un second facteur. Seul un TOTP activé demande un code. Vérifier en navigation privée.
:::

## AppSec

Le bouncer envoie chaque requête à `crowdsec:7422` avant de la laisser passer.
Collections `crowdsecurity/appsec-virtual-patching` et `crowdsecurity/appsec-generic-rules`
dans `default.nix`, réglages du bouncer dans `docker-pangolin.nix`.

- Le blocage en ligne ignore la whitelist du parsing : les requêtes du tailnet et du LAN sont inspectées aussi.
- crowdsec tombé, toute requête est bloquée (fermé par défaut, comme la LAPI en mode `live`).
- Seuls les 10 premiers Mo d'un corps sont inspectés : les gros envois (immich, papra) passent.

## Vérifications

```bash
# Bouncer enregistré, log d'accès lu
sudo docker exec crowdsec cscli bouncers list
sudo docker exec crowdsec cscli metrics show acquisition

# Adresse vue par traefik (doit être celle du visiteur)
sudo tail -n 3 /srv/docker/pangolin.friloux.me/traefik-logs/access.log \
  | nix run nixpkgs#jq -- -r '[.ClientHost, .RouterName, .DownstreamStatus] | @tsv'

# Test de ban (5 min), attendre 70 s avant de tester
sudo docker exec crowdsec cscli decisions add --ip <IP> --duration 5m --reason test

# AppSec : attendu 403
curl -sS -o /dev/null -w '%{http_code}\n' https://cuisine.friloux.me/.env

# Une requête légitime en 403 : trouver la règle avant de désactiver quoi que ce soit
docker exec crowdsec cscli alerts list | grep -E "vpatch|appsec"
```

## Sauvegarde, santé, alertes

| Quoi | Où | Détail |
|---|---|---|
| Borg | `backup.nix` | 04:00 vers `storage2.friloux.me/~/skitarii.friloux.me`, `borg check` hebdo. [Restauration](/nixos/fr/operations/restore/) |
| Copies SQLite | `/srv/docker/sqlite-snapshots` | pangolin, crowdsec, crowdsec-manager, faites avant `borg create` |
| Rotation des logs | `docker-pangolin.nix` | `access.log` quotidien, 14 gardés, renommage puis `USR1` |
| Healthchecks | `docker-pangolin.nix` | pangolin `:3001/api/v1/`, gerbil `:3004/healthz`, `traefik healthcheck` |
| Alertes conteneurs | `default.nix` | `stc.relics.docker.notify`, topic ntfy dans sops |
| Alertes nœuds et ressources | UI pangolin (base, sauvegardée) | règles *site toggle* et *resource toggle*, webhook ci-dessous |

Webhook pangolin : `POST https://ntfy.sh/` (la racine, où ntfy lit un corps JSON), body template actif :

```json
{"topic":"TOPIC","title":"[pangolin] site {{siteName}} {{status}}","message":"{{event}} à {{timestamp}}"}
```

Règle des ressources : `{{resourceName}}` au lieu de `site {{siteName}}`. Les événements de ressource demandent un health check sur la cible.

## Pièges connus

| Symptôme | Cause | Correctif |
|---|---|---|
| Toutes les routes du dashboard tombent : `invalid middleware "badger@file"` | badger v1.8.0 échoue au contrôle d'intégrité, traefik coupe tous les plugins | badger figé en v1.7.0 (traefik/traefik#14115) |
| Le test de ban renvoie 200 | le bouncer `live` garde une IP propre 60 s en cache | attendre |
| Visiteurs IPv6 vus avec une adresse privée | pas d'IPv6 sur le réseau Docker, `docker-proxy` sur le chemin | /64 ULA sur le réseau. Pour le changer : arrêter les conteneurs, `docker network rm pangolin` |
| Pas de notification ntfy, pas d'erreur | ntfy.sh limite l'IPv6 par /64, partagé avec les voisins OVH (`429`) | `curl -4 --fail` partout |
| `{{resourceName}}` non remplacé | le bouton *Test* du dashboard envoie de fausses données | les vraies alertes sont bonnes |
| `connection refused` sur `pangolin:3001`, `no such host crowdsec`, `crowdsec@file does not exist` au démarrage | ordre de démarrage | disparaît en quelques secondes ; sinon, c'est réel |
